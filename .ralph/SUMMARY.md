Adds spec 28: an epic's pieces may declare `dependsOn` siblings (0-based indexes in the breakdown editor, the breakdown API and the scoping split proposal's new `DEPENDS ON:` line), persisted as sibling card ids in a new nullable `cards.depends_on` column (migration 0022). A third run mode, `graph`, starts a piece once every dependency is Done or Abandoned, bounded by the per-repo cap; `ordered` and `parallel` are unchanged and pre-existing epics carry no dependencies. Cycles and dangling/self references are rejected at breakdown time with an error naming the pieces; a piece that starts past an abandoned dependency records `epic.dependency_abandoned` on the epic; the Work feed's epic group lists what each queued piece is waiting on. Covered by unit tests for the hold rule and cycle detection, lifecycle tests for the cap/dependency start order and Start now, and a three-piece graph epic in the mock-provider pipeline test.
