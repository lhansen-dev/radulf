Cards now remember the Jira issue they came from: a nullable `cards.jira_key` (migration `0026_jira_key`) is set by the New Task dialog on import (each imported child piece carries its own key), accepted or cleared via `POST`/`PATCH /api/cards`, round-tripped by card export/import, and shown on the card page as a link to `<jiraBaseUrl>/browse/<key>`.

With the new opt-in setting `jiraCommentOnDone` (default off, toggle in Settings → Jira), reaching Done — review merge, PR delivery, or an epic parent closing — posts exactly one plain-text comment on the issue (title, merged-into-branch-at-sha or PR URL, and the card link from `RADULF_PUBLIC_BASE_URL` or the bare id) using the same basic-auth REST v2 path as the import. One attempt with a bounded timeout; success and failure land on the card timeline as `jira.commented` / `jira.comment_failed` and never block the card. Docs updated in HOW_IT_WORKS.md, GETTING_STARTED.md and PRODUCT.md.
