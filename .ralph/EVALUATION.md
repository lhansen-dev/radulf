## For the human reviewer

- **Docker is not available in this sandbox**, so the compose-level criteria (one web + one worker up, web without relaxations, mock-provider pipeline through review with sandboxed bash in the worker, `--scale worker=2` with cap contention) were verified only structurally. Please run `make check-compose` and the mock-provider pipeline on a Docker host.
- `make check-compose` is a thin smoke: `up -d --build --scale worker=2 && ps && down -v`. It does not `--wait` for the health checks, so it succeeds as soon as containers *start*, and it does not drive a pipeline. Also, the `web` service publishes fixed `127.0.0.1:53692` and `127.0.0.1:1455` (pi OAuth callbacks), so `check-compose` will fail with "port is already allocated" if the operator's own stack is running, and because the recipe chains with `&&`, a failed `up` skips `down -v` and leaves the `radulf-check` project behind. Consider `up -d --wait` and a trap/`;`-chained teardown.
- `stopRequests()` in `improvementRuns.ts` is still in-process. In the split topology a Stop issued from the web container is never seen by the worker driving the run, so the run ends labelled `completed` instead of `stopped`. This predates this card (since web-only insert landed) and the existing comment calls it a labelling nicety, but now it is the *default* deployment shape rather than a restart edge case.
